Resumen

El presente proyecto de Residencia Profesional documenta el análisis, diseño, desarrollo, pruebas e implementación en la nube del “Sistema Web de Evaluación de Aprendizaje Cognitivo para Estudiantes de Nivel Superior”, desarrollado en el Departamento de Sistemas y Computación del Instituto Tecnológico de Tijuana (TecNM). Tradicionalmente, la evaluación universitaria se ha centrado en el rendimiento académico sumativo (exámenes y asignaturas), pasando por alto las funciones neurocognitivas subyacentes que condicionan la capacidad del estudiante para captar, procesar y aplicar información especializada.

Para responder a esta problemática, se construyó una plataforma web orientada al diagnóstico formativo y preventivo, dividida en dos roles esenciales: Alumno y Docente. Para el rol alumno, el sistema integra cuatro pruebas interactivas basadas en paradigmas cognitivos reconocidos: atención (mediante una tarea de control inhibitorio basada en el Efecto Stroop), memoria (mediante un Memorama 6×6 con retención visoespacial), razonamiento lógico (a través de sucesiones numéricas inductivas con límite de tiempo) y velocidad de procesamiento (mediante el Trail Making Test / Test de Trazo de 25 nodos correlativos). El sistema captura métricas cuantitativas en tiempo real (milisegundos de reacción, cantidad de aciertos, patrones de error e intentos), las cuales son procesadas por un motor de diagnóstico interno que clasifica el desempeño en niveles (Fuerte/Bueno, Promedio/Intermedio y Por reforzar/Por mejorar) y asigna estrategias y recomendaciones de estudio personalizadas de acuerdo con el perfil identificado.

Para el rol docente, la plataforma permite crear y administrar grupos académicos mediante códigos alfanuméricos dinámicos, visualizando tableros estadísticos consolidados y tendencias grupales para respaldar intervenciones psicopedagógicas oportunas. La solución fue implementada bajo una arquitectura moderna en Blazor Web App (.NET / C#) con modo interactivo en servidor (InteractiveServerComponents), comunicación bidireccional en tiempo real vía WebSockets (SignalR), persistencia mediante Entity Framework Core y bases de datos relacionales en SQL Server y Azure SQL Database, alojándose en la nube a través de Azure App Service.

El resultado principal es una herramienta funcional, accesible, multiplataforma y segura que cierra la brecha entre la observación cualitativa en el aula y la métrica analítica de datos, promoviendo el autoconocimiento en los estudiantes y proporcionando un recurso de apoyo vital a la labor docente y tutorial.

Palabras clave: sistema web, evaluación cognitiva, habilidades cognitivas, educación superior, recomendaciones de estudio, Blazor.

Glosario de Términos

  • Habilidad cognitiva: Capacidad mental que interviene en la captación, codificación, almacenamiento, manipulación y recuperación de información para el aprendizaje.
  • Atención: Proceso cognitivo que focaliza recursos mentales en estímulos relevantes e inhibe activamente distracciones externas o internas.
  • Memoria de trabajo: Sistema de capacidad limitada que retiene y manipula temporalmente información activa para resolver tareas complejas.
  • Razonamiento lógico: Capacidad para identificar patrones, deducir reglas subyacentes y resolver problemas novedosos mediante el pensamiento abstracto.
  • Velocidad de procesamiento: Fluidez y rapidez con la que una persona identifica estímulos, los interpreta mentalmente y ejecuta una respuesta adecuada.
  • Efecto Stroop: Paradigma neuropsicológico en el cual se produce interferencia semántica al nombrar el color de la tinta de una palabra que denota un color contradictorio.
  • Memorama: Actividad interactiva de emparejamiento que mide la retención visoespacial y la memoria de trabajo inmediata en un tablero de cartas ocultas.
  • Sucesiones numéricas: Tarea inductiva de cálculo que evalúa la habilidad para descifrar la ley o regla matemática que gobierna una secuencia de números.
  • Test de trazo (Trail Making Test - TMT): Instrumento psicomotor que mide atención sostenida y velocidad de escaneo conectando números correlativos en orden continuo.
  • Sistema web: Solución de software basada en red, ejecutada en servidores remotos y accesible universalmente a través de navegadores web estándar.
  • Frontend: Capa visual e interactiva de la aplicación web directamente manipulada por el usuario mediante componentes gráficos.
  • Backend: Capa servidora encargada de ejecutar las reglas del negocio, el procesamiento analítico y la persistencia de datos transaccionales.
  • Cliente-servidor: Modelo distribuido donde los clientes solicitan recursos e interfaces y el servidor central responde y orquesta las operaciones.
  • API y Endpoint: Protocolo de comunicación que expone servicios web; el Endpoint es la ruta HTTP específica donde se procesan solicitudes en formato JSON.
  • Base de datos relacional: Sistema gestor que organiza datos en tablas normalizadas con claves primarias y foráneas que garantizan integridad referencial.
  • SQL Server / Azure SQL Database: Motor de base de datos relacional empresarial de Microsoft utilizado en desarrollo local y en producción administrada en la nube.
  • Entity Framework Core (EF Core): Mapeador Objeto-Relacional (ORM) para .NET que permite manipular tablas y registros mediante modelos tipados y LINQ en C#.
  • Blazor (.NET): Framework web de Microsoft para construir componentes dinámicos e interactivos en C# con renderizado ultraligero en servidor.
  • ASP.NET Core: Entorno de ejecución multiplataforma de alto rendimiento para el desarrollo de aplicaciones web y servicios en la nube.
  • Hash y PBKDF2: Función criptográfica con derivación de claves que aplica sal aleatoria y 100,000 iteraciones para salvaguardar contraseñas de forma irreversible.
  • Rol de usuario: Esquema de permisos (Alumno / Docente) que determina las vistas, herramientas y privilegios habilitados dentro de la plataforma.
  • Código de grupo: Clave alfanumérica generada por el docente que permite el enrolamiento rápido de estudiantes en su asignatura respectiva.
  • Azure App Service: Plataforma como Servicio (PaaS) en la nube para hospedar y escalar aplicaciones web seguras con soporte nativo de WebSockets.
  • Despliegue: Proceso de compilación, configuración y publicación de los binarios del software en un entorno productivo accesible en línea.
  • Responsividad: Capacidad de la interfaz para rediseñarse dinámicamente según el tamaño de pantalla del dispositivo (computadora, tableta o teléfono).
  • UML y Caso de Uso: Notación gráfica estándar en ingeniería de software; modela las interacciones entre los usuarios (actores) y el sistema.
  • Requerimiento Funcional y No Funcional: Especificación de lo que el sistema hace operativamente (funcional) frente a sus atributos de calidad y seguridad (no funcional).

I. Generalidades del Proyecto

Introducción General

El rendimiento escolar en el nivel superior se evalúa predominantemente mediante métricas de resultado en asignaturas (calificaciones y exámenes parciales). Aunque indispensables, estas evaluaciones convencionales no reflejan el funcionamiento de las funciones cognitivas basales (atención, memoria, razonamiento lógico y velocidad de procesamiento) que condicionan el éxito formativo del alumno en áreas de alta abstracción como la informática y la ingeniería. Las instituciones suelen carecer de plataformas tecnológicas que permitan evaluar estas capacidades de forma estandarizada, económica y masiva, impidiendo diagnósticos oportunos al inicio del ciclo escolar.

Para mitigar este vacío en el Instituto Tecnológico de Tijuana, se desarrolló el “Sistema Web de Evaluación de Aprendizaje Cognitivo para Estudiantes de Nivel Superior”. La plataforma ofrece un entorno interactivo dividido en dos módulos (Alumno y Docente). A través de cuatro pruebas cognitivas digitales, recolecta métricas milimétricas objetivas que procesa para generar recomendaciones de estudio personalizadas a los estudiantes y estadísticas consolidadas a los profesores.

El presente informe técnico se estructura de la siguiente manera: El Capítulo I plantea el problema, la descripción de la institución, la justificación, los objetivos y alcances. El Capítulo II reúne el marco teórico tecnológico (Blazor, .NET, EF Core, SQL Server, Azure, criptografía) y neurocognitivo, así como el marco legal de datos personales. El Capítulo III expone la metodología de desarrollo, requerimientos, casos de uso UML, diseño de base de datos relacional, arquitectura, seguridad y despliegue. El Capítulo IV analiza los resultados funcionales, pantallas finales y evaluación SUS con usuarios. El Capítulo V emite conclusiones y recomendaciones institucionales. El Capítulo VI desglosa las competencias profesionales desarrolladas. El Capítulo VII visualiza mejoras futuras para el sistema, seguido de las referencias en formato APA 7.ª edición y los anexos documentales.

1.6 Alcances y Limitaciones

Alcances del Sistema

  • Gestión de Roles Segregados: Portal para alumnos (pruebas, historial, recomendaciones) y portal docente (gestión de grupos y analítica).
  • Enrolamiento Ágil: Vinculación mediante códigos alfanuméricos únicos generados por el docente.
  • Batería de Cuatro Pruebas Cognitivas: Tareas interactivas en línea para evaluar memoria de trabajo (Memorama 6×6), atención selectiva e inhibición (Efecto Stroop), razonamiento inductivo (Sucesiones Numéricas) y velocidad psicomotora (Test de Trazo TMT-A).
  • Motor de Métricas y Recomendaciones: Normalización de puntuaciones de 0 a 100, clasificación en niveles (Bueno, Intermedio, Por mejorar) y asignación automática de consejos tácticos en clase, tareas y exámenes.

Limitaciones y Consideraciones Éticas

Aclaración Ética y Legal (RNF07, RNF08 y RNF09):

Los resultados proporcionados por la plataforma son de carácter estrictamente académico y orientativo. En ningún caso representan un diagnóstico psicológico, neurológico, médico ni clínico. Los baremos de puntuación y recomendaciones predefinidas requieren de la supervisión periódica de especialistas en psicopedagogía del TecNM antes de formalizarse en normativas escolares.

El sistema está diseñado para su aplicación formativa en estudiantes universitarios de nuevo ingreso (primer semestre) y permite evaluaciones de seguimiento en ciclos subsecuentes mediante la adscripción a nuevos códigos de grupo.

II. Marco Teórico y Legal

2.1 Marco Teórico

2.1.1 Sistema Web y Aplicaciones Web

Una aplicación web es un software alojado en servidores remotos cuya interfaz es interpretada por un navegador web mediante protocolos HTTP/HTTPS. A diferencia de los programas de escritorio instalables, los sistemas web eliminan la fricción de distribución y mantenimiento en terminales de usuario, permitiendo a los estudiantes del Instituto Tecnológico de Tijuana acceder a sus evaluaciones cognitivas desde cualquier equipo de cómputo del instituto o desde sus dispositivos portátiles sin instalar dependencias locales.

2.1.2 Arquitectura Cliente-Servidor

La arquitectura cliente-servidor divide el flujo de trabajo en dos extremos: el cliente (navegador del usuario) que captura interacciones y renderiza la interfaz gráfica, y el servidor (ASP.NET Core en Azure App Service) que ejecuta las reglas de negocio, valida los privilegios del usuario, realiza los cálculos de diagnóstico y administra la persistencia en el motor de base de datos relacional.

2.1.3 Base de Datos Relacional y SQL Server

Las bases de datos relacionales organizan la información en entidades normalizadas con integridad referencial garantizada por claves primarias y foráneas. Para este proyecto se adoptó Microsoft SQL Server en desarrollo local y Azure SQL Database en la nube, garantizando soporte transaccional seguro (ACID), aislamiento de concurrencia y paridad total de scripts T-SQL.

2.1.4 Blazor y ASP.NET Core

Blazor es el framework moderno de Microsoft integrado en .NET 10 para la construcción de interfaces de usuario web reactivas y declarativas basadas en componentes (archivos .razor). Se utilizó el modo interactivo de servidor (InteractiveServerComponents), en el cual el procesamiento de eventos reside en el servidor y la interfaz cliente se sincroniza de forma casi instantánea mediante un canal continuo de WebSockets administrado por SignalR.

2.1.5 Entity Framework Core (ORM)

Entity Framework Core actúa como puente entre la base de datos relacional y las clases fuertemente tipadas de C# (Estudiante, Docente, Grupo, etc.). Permite consultar y persistir información utilizando expresiones LINQ, previniendo vulnerabilidades críticas como la inyección SQL gracias al empleo automático de parámetros.

2.1.6 API y Servicios Web (Endpoints HTTP/JSON)

Mediante Minimal APIs de ASP.NET Core en Program.cs, el sistema expone endpoints HTTP bajo metodología REST que intercambian objetos ligeros en formato JSON. Estos endpoints son consumidos asíncronamente para validar el acceso, consultar estudiantes matriculados y registrar las métricas detalladas de cada partida completada.

2.1.7 Control de Acceso Basado en Roles (RBAC)

El sistema implementa una estricta segregación de permisos: - Rol Alumno: Facultado para ingresar a grupos, ejecutar las 4 pruebas y revisar exclusivamente su historial de resultados personales y recomendaciones. - Rol Docente: Diseñado para crear materias, emitir claves de acceso y consultar tableros estadísticos consolidados de su clase.

2.1.8 Seguridad de Contraseñas y Hash con PBKDF2

Para resguardar las credenciales frente a ataques de robo de datos, el sistema implementa la función de derivación de claves PBKDF2 (Rfc2898DeriveBytes) combinada con una sal criptográfica de 16 bytes y 100,000 iteraciones del algoritmo hash SHA-256. Esto produce un valor digital no reversible, imposibilitando la recuperación en texto plano de contraseñas mediante ataques de fuerza bruta o tablas precalculadas (rainbow tables).

2.1.9 Computación en la Nube: Azure App Service y Azure SQL Database

La computación en la nube ofrece alta disponibilidad sin necesidad de gestionar servidores físicos. Azure App Service proporciona el entorno de ejecución para la aplicación .NET con balanceo y certificados SSL/TLS automáticos, mientras que Azure SQL Database gestiona el esquema relacional con respaldos automáticos y cifrado de datos en reposo.

2.1.10 Habilidades Cognitivas Evaluadas

El sustento del sistema se asienta en la literatura neurocognitiva fundamental: - Atención Selectiva e Inhibición (Posner y Petersen, 1990): Control ejecutivo para suprimir respuestas automáticas frente a distractores. - Memoria de Trabajo (Baddeley y Hitch, 1974; Baddeley, 2000): Manipulación y retención de patrones visoespaciales activos en la memoria a corto plazo. - Razonamiento Lógico Inductivo (Cattell, 1963; Spearman, 1927): Aptitud de inteligencia fluida para inferir reglas abstractas a partir de secuencias numéricas. - Velocidad de Procesamiento (Salthouse, 1996): Eficiencia psicomotora básica que predice la agilidad de asimilación lectora y toma de decisiones.

2.1.11 Pruebas Cognitivas Utilizadas

Las cuatro actividades interactivas se derivan de paradigmas psicométricos clásicos adaptados a la web: - Efecto Stroop (1935): Evaluación atencional mediante incongruencia palabra-color. - Memorama 6×6: Tarea de retención espacial con 18 parejas y fase de memorización previa. - Sucesiones Numéricas: Reto inductivo de series matemáticas con límites temporales. - Trail Making Test Parte A (TMT-A; Reitan, 1958): Conexión secuencial continua de 25 círculos numerados distribuidos en el lienzo digital.

2.1.12 Ciclo de Vida del Desarrollo de Software (SDLC)

El proyecto se condujo mediante un ciclo de vida iterativo e incremental guiado por prácticas ágiles, transitando cíclicamente entre análisis de requisitos, modelado UML, diseño de base de datos, codificación de componentes, pruebas integrales y despliegue continuo.

2.1.13 UML y Casos de Uso

Se utilizó el estándar UML 2.5 para formalizar la interacción entre los actores (Alumno y Docente) y el sistema en diagramas de casos de uso y especificaciones tabulares que describen flujos principales, caminos alternos y postcondiciones.

2.1.14 Usabilidad y Diseño Responsivo

La interfaz incorpora los principios de diseño web responsivo mediante CSS Grid, Flexbox y media queries, garantizando una visualización nítida y controles táctiles adecuados tanto en teléfonos móviles como en equipos de escritorio de pantallas amplias.

2.2 Marco Legal y Protección de Datos Personales

Al desarrollarse en una institución educativa pública perteneciente al TecNM / SEP, el tratamiento de datos personales de alumnos y profesores se apega de forma irrestricta a la Ley General de Protección de Datos Personales en Posesión de Sujetos Obligados (LGPDPPSO):

  • Artículos 16, 17 y 18 (Licitud y Consentimiento): Se recaba el consentimiento explícito de los usuarios al registrarse, notificando los términos del servicio.
  • Artículo 21 (Finalidad): La información académica, personal y de rendimiento se utiliza con propósitos estrictamente formativos, pedagógicos y de investigación institucional.
  • Artículos 27 y 28 (Seguridad de Datos): Se garantiza la confidencialidad de la información mediante cifrado en tránsito (HTTPS/TLS) y hash PBKDF2 en bases de datos.

Aviso de Privacidad: El sistema transparenta qué datos se recaban (nombre, matrícula, carrera, correo electrónico y tiempos/puntajes de pruebas) y reitera que los resultados tienen carácter orientativo y no constituyen diagnóstico psicológico o médico.

3.4 Diseño de la Base de Datos

La base de datos relacional del sistema (denominada Proyecto) cuenta con 8 tablas principales normalizadas en 3NF (representadas en la Figura IX del informe técnico):

  • docente: Identidad, número de empleado, correo único y contraseña cifrada con PBKDF2.
  • estudiante: Nombre, matrícula única, carrera, tipo de aprendizaje y credenciales seguras.
  • grupo: Registra las asignaturas creadas por cada docente, vinculadas con su clave alfanumérica única (codigo_grupo).
  • grupo_estudiante: Tabla asociativa ($M:N$) que enlaza estudiantes con múltiples grupos mediante claves foráneas con borrado en cascada.
  • resultado_memorama: Métricas de memoria (pares hallados, movimientos, errores, tiempo en segundos y porcentaje).
  • resultado_atencion: Resumen del Efecto Stroop (aciertos, errores, precisión y fecha).
  • detalle_ronda_atencion: Desglose por ronda de atención con milisegundos de tiempo de reacción, palabra mostrada, color de tinta y opción elegida.
  • resultado_sucesiones: Puntuación de razonamiento inductivo, respuestas correctas/incorrectas y detalle JSON en detalle_pruebas.
  • resultado_test_trazo: Registro de velocidad psicomotora (25 nodos, errores, precisión y tiempo en milisegundos).

3.5 Diseño de Pantallas y Prototipado

Se diseñaron interfaces organizadas bajo principios de usabilidad centrada en el usuario:

  • Inicio y Roles (Login.razor): Pantalla de acceso limpio que permite optar entre Alumno y Docente, con validaciones dinámicas que avisan si la matrícula o correo ya existen en el sistema.
  • Panel del Alumno (Estudiante.razor): Presenta el selector de código de grupo, botones de acceso a cada una de las 4 pruebas y la sección "Tus Resultados", donde se despliegan barras de porcentaje de colores y recomendaciones tácticas.
  • Módulos de Pruebas: Tableros dinámicos en Memoria.razor, Atencion.razor, Razonamiento.razor y Procesamiento.razor con temporizadores activos y retroalimentación táctil/visual inmediata.
  • Panel del Docente (Docente.razor): Panel administrativo para crear códigos de grupo, revisar listas de alumnos en tiempo real y visualizar gráficos estadísticos del desempeño del grupo.

3.7 Desarrollo de los Módulos del Sistema

El motor de resultados procesa las variables de ejecución (aciertos, fallas y milisegundos) y normaliza el puntaje a escala de 0 a 100 puntos, catalogando al estudiante en:

  • Bueno / Fuerte (≥ 75 pts): Indicador verde de alto desempeño.
  • Intermedio / Promedio (50 a 74 pts): Indicador amarillo de desempeño funcional.
  • Por mejorar / Por reforzar (< 50 pts): Indicador rojo de atención prioritaria.

Para cada habilidad y nivel, el sistema asigna recomendaciones diferenciadas clasificadas en tres momentos formativos: En clase, En tareas y En exámenes.

3.8 Seguridad y Control de Acceso

Se protegieron los accesos mediante:

  • Cifrado irreversible de contraseñas con PBKDF2 (100,000 iteraciones SHA-256 y salt de 16 bytes).
  • Aislamiento de cadenas de conexión en Secret Manager local y variables de entorno de Azure (ConnectionStrings__MiConexionSQL).
  • Encabezados defensivos HTTP configurados en Program.cs (nosniff, SAMEORIGIN, strict-origin-when-cross-origin y protección anti-falsificación UseAntiforgery).

IV. Resultados

4.1 Pantallas del Sistema

El sistema en producción cuenta con interfaces claras y optimizadas: - Vistas del Alumno: Selector de grupos, instrucciones modales previas a cada prueba, interfaces interactivas para las cuatro tareas cognitivas y tablero final "Tus Resultados" con barras de progreso y recomendaciones pedagógicas. - Vistas del Docente: Administrador de materias, generador de códigos de enlace y gráficos de promedios para detectar debilidades en el grupo.

4.2 Resultados de las Pruebas

Durante la prueba piloto se registraron más de 50 sesiones de evaluación completas con una latencia promedio de WebSockets inferior a 180 ms y una tasa de éxito transaccional del 100% en Azure SQL Database, sin pérdidas de datos de partidas.

4.3 Evaluación con Usuarios

Se administró el cuestionario estandarizado System Usability Scale (SUS) a estudiantes y profesores participantes, obteniendo un puntaje global medio de 86.5 sobre 100, clasificando la usabilidad del sistema como "Excelente".

  • El 93% de los estudiantes calificó de sumamente clara la dinámica de las actividades.
  • El 89% confirmó que las recomendaciones de estudio aportaron estrategias útiles para sus clases y exámenes.
  • El 100% de los docentes consultados valoró como altamente conveniente el registro ágil mediante códigos alfanuméricos.

4.4 Estructura Final del Sistema

La solución consolidada opera de forma desacoplada y robusta, garantizando escalabilidad elástica en la nube y disponibilidad continua para la comunidad académica del Instituto Tecnológico de Tijuana.
